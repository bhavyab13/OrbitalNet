# Service contracts (all streams build against this)

Ports (local dev): sim **8000** · operator PHISAT-2 **7001** · operator EDRS-C **7002** · operator STARLINK-3005 **7003** · marketplace MCP **3000** (`/mcp`) · dashboard **5173**.
Every service reads `data/scenario.json` (path via env `SCENARIO=…`). Node ≥22 for TS packages (`export PATH=/opt/homebrew/opt/node@22/bin:$PATH`). Python 3.11 + uv for `sim/`.
Sim time is integer seconds `sim_t` from scenario epoch. Real time ↔ sim time via `accel`.

## Keys
`keys/<kid>.json` = `{"kid":"…","public_key":"base64url","private_key":"base64url"}` (Ed25519, generated by `scripts/gen-keys.{py,ts}` if missing). kids: `world`, `broker`, `orbital-foundry`, `lumen-relay`, `northstar-relay`. Public keys are also served by each service (`GET /keys`).
Canonical JSON for signing: keys sorted recursively, separators `(",",":")`, UTF-8; `sig` = base64url Ed25519 over that; `kid` included in the signed body.

| POST | `/reset` | | reload scenario, sim_t=0 |
| WS | `/ws` | | JSON events: `{type, sim_t, …}`; types: `tick`, `window_open`, `window_close`, `transfer_progress {window_id, from, to, bytes_moved_mb, bytes_total_mb, pct}`, `leg_start`, `leg_done {attestation}`, `mission_status`, `payment {operator_id, amount_usd, method, receipt_ref}`, `grant_issued`, `grant_rejected {reason}`, `link_killed`, `provider_online`, `replan_required`, `plan_chosen`, `delivered`, `infeasible`, `narration {text, act}` |

Runner semantics (env `METERED_RELAY=1` default: relay downlink legs are carried through the broker's `/transfer/stream` metered session instead of the local byte-mover + `/transmit`; falls back to the one-shot path when the relay has no metered endpoint): for each leg in order → wait for window open → move bytes at `bandwidth_mbps` (progress events every tick; if window closes first → leg FAILED, mission REPLAN_REQUIRED) → for compute leg: POST operator `/execute` with `{grant, world_assertion, payload_url: sim URL of the scene, params}`; apply `modeled_compute_s` to clock; store result at that node (`committed`) → for final downlink leg: POST relay `/transmit` with `{grant, world_assertion, payload_b64 (the result)}` → DELIVERED. Any operator `403` → `grant_rejected` event + REPLAN_REQUIRED. Killed window → `link_killed` + REPLAN_REQUIRED; the sim also asks the affected operator for `/refund` for any unfulfilled paid grant on that window.

Planner: time-expanded DFS over windows (depth ≤ 4). Transfer time = bytes_mb*8/bandwidth_mbps; must start ≥ now and ≥ previous leg end and finish ≤ window end. Compute leg occupies `modeled_compute_s` after the input transfer completes on that node (window not needed for compute itself). Delivery = end of a downlink leg. Cost = Σ matching quote prices (if a quote for a window is missing, planner marks the plan `feasible:false, reason:"no quote"`). Always include the three canonical candidates: own-downlink, raw-relay (every direct relay route), compute+relay (every compute node × relay route) plus any 3–4 hop variants found.


**Implementation notes (sim, as built — deviations from the table above):**
- `/plan` plans carry `feasible` (physics + deadline + budget only) **and** a separate `quoted: bool`. A plan with missing quotes is NOT marked infeasible; its priced legs carry `price_estimated: true` (estimate from the provider manifest) and `notes` says so. Extra fields: `strategy` (`own-downlink|raw-relay|compute+relay|relay`), `operator_id` on every leg. `/plan` defaults every mission field from the scenario, so `{"now_sim_t":0}` is a valid body; if the mission already has `committed` state and the body omits `committed`, the planner replans from the committed node with the remaining budget.
- **Pricing/grant convention:** compute node → one quote keyed `(compute_node, ingest window)`; price sits on the `compute` leg, whose `window_id` is the ingest window. Relay node → one quote keyed `(relay_node, downlink window)`; price sits on the downlink `transfer` leg. Crosslinks into a relay and own-operator legs are free. Grants are keyed by **leg index** (`grants: {"1": Grant, "3": Grant}`); the runner needs a grant on every `compute` leg and every relay downlink leg (`/transmit` is called at window open, before bytes move).
- Extra endpoints: `GET /scenario`, `GET /keys`, `POST /missions/{id}/infeasible {reason}` (buyer/broker declares honest failure → `INFEASIBLE`), `/missions/{id}/resume` accepts optional `refunded_usd`. Mission objects track `total_paid_usd`, `budget_remaining_usd`, `replans`, `committed`, `arrival_sim_t`, `delivered_sim_t`, `previous_plans`.
- `kill_link` on a window with a paid, unfulfilled grant calls that operator's `POST /refund {grant_id, reason, mission_id}` and, on 200, restores the mission budget and emits `refund`.
- Extra events: `plans_computed`, `fulfilment_request`, `leg_failed`, `link_restored`, `competing_mission`, `revoked`, `refund`, `clock`, `reset`, `hello` (first ws frame, full state).

## 2. Operator service (TypeScript/Hono, one codebase, config per node)
Env: `NODE_ID`, `OPERATOR_ID`, `KID`, `PORT`, `SIM_URL`, `WORLD_PUBKEY` (or fetched from `SIM_URL/keys`), `PAY_RAIL=tempo|stripe|mock`, `TEMPO_RECIPIENT`, `STRIPE_SECRET_KEY`, `STRIPE_PROFILE_ID`, `MPP_SECRET_KEY`, `BROKER_URL` (self-register on boot), `PUBLIC_URL`.
| Method | Path | Notes |
|---|---|---|
| GET | `/.well-known/ocgp.json` | signed Manifest (see PROTOCOL §2.1); includes `base_url`, live `capacity` |
| GET | `/keys` | `{kid, public_key}` |
| GET | `/status` | `{node_id, capacity:{…}, power_wh, grants:{active, fulfilled, revoked}, ledger:[…]}` |
| POST | `/quote` | `{mission_id, capability, window_id, units:{mb?|compute_s?}, now_sim_t}` → signed Quote. Price `p0 + α·d/max(c,ε)` (+ `price_per_mb*mb` or `price_per_compute_s*s`), floor `price_min_usd`. **Denies** if units exceed limits/policy (`403 ocgp/policy`) |
| POST | `/hold` | `{quote_id, ttl_s}` → `{hold_id, expires_sim_t}`; reduces available capacity until expiry/commit |
| POST | `/reserve` | **MPP-gated** (`mppx/hono` `charge({amount: quote.price_usd})`). Body `{quote_id, hold_id?, mission_id, holder}` → **Grant** (PROTOCOL §2.4) with `payment.receipt` from the MPP receipt. Capacity committed. Emits to sim `POST /events` `{type:"payment"…}` and `{type:"grant_issued"}` |
| POST | `/execute` | compute nodes. `{grant, world_assertion, payload_url|payload_b64, params}` → verifies (§2.6) → runs **real inference** (`inference/fire_detect.py` via child process, or TS port) → `{result:{geojson, summary:{fire_pixels, clusters, max_frp_proxy, bbox}, thumbnail_b64}, attestation}`; deducts power; marks grant fulfilled |
| POST | `/transmit` | relay nodes. `{grant, world_assertion, payload_b64}` → verifies incl. `bytes ≤ limits` and window open → `{attestation}` |
| POST | `/transmit/stream` | relay nodes, **MPP session-gated** (§2.10). Body as `/transmit` plus `bytes_mb`. Verifies grant + world assertion first (403 JSON, unmetered), then streams one SSE event per 100 KB `{unit, units_total, mb_moved, mb_total, usd_accrued}` (each event = one charged unit at `price_per_mb/10`), final event `{done:true, attestation (with .metered), metered_usd}`. Emits `metered_start`, `metered_usage` (every 5 units), `grant_fulfilled`, `metered_settled {total_usd, units, rail, settlement_refs:[txHash…]}`. Env: `TEMPO_OPERATOR_KEY_<operator_id_with_underscores>` (settlement signer, needs testnet gas), `TEMPO_DEPOSIT_ADDRESS` (Stripe rail). |
| GET | `/metered` | `{enabled, rail, unit_usd, unit_type, endpoint, settler, settlements:[{txHash, channelId, trigger, amount_usd, delta_usd, at}]}` |
| POST | `/refund` | `{grant_id, reason}` → Refund Voucher if grant unfulfilled and provider-side cause |
| POST | `/admin/revoke` | `{grant_id?|all_unfulfilled:true}` (operator key or `ADMIN_TOKEN`) → revokes + refund vouchers |
| POST | `/admin/capacity` | `{fraction_taken, label}` → simulates competing demand; subsequent quotes reprice |
Rejections are `403 {"error":"ocgp/grant-rejected","reason":"window_closed|bad_signature|revoked|already_used|expired|payload_too_large|op_not_allowed|bad_world_assertion"}`.
On boot: generate/load key, build manifest, `POST BROKER_URL/registry {manifest_url}` (retry), and `POST SIM_URL/events {type:"provider_online"}`.


### 2.1 Implementation notes (as built in `packages/operator`, deviations from the table above)
- `POST /quote`: `now_sim_t` is optional; if omitted the node asks the World (`SIM_URL/state`). Quotes expire 300 sim-s after issue. Compute quotes default `units.compute_s` to the node's `modeled_compute_s`. Policy denials: `403 {"error":"ocgp/policy","reason":…}`.
- `POST /reserve`: body `{quote_id, hold_id?, holder, model?}`; unpaid → **402** MPP challenge (`WWW-Authenticate: Payment …`); paid → `{grant, receipt}` + `Payment-Receipt` header. Grant carries `quote_id` and `payment.receipt` (Tempo: `reference` = tx hash). Errors: `404 ocgp/unknown-quote`, `409 ocgp/quote-expired | ocgp/hold-expired | ocgp/no-capacity`.
- Extra routes: `POST /hold/release {hold_id}`, `POST /admin/power {power_wh}` (admin), `GET /scene` (serves the scenario image for local dev).
- Extra rejection reason: `wrong_node` (grant names another node/operator). Rejection order: parse → node → own sig → revoked → used → world sig → window id → open → validity → window bounds → op/model → size.
- `/execute` body: `{grant, world_assertion, payload_url | payload_b64, params:{payload_mb?, op?, bbox?, truth_csv?}}`. `params.payload_mb` is the **modeled** scene size (checked against `limits.max_input_mb` together with the real byte count). Response `{result:{model, geojson, summary, validation, thumbnail_b64 (JPEG ~17 KB), result_bytes}, attestation}`; attestation `sim_t_end = sim_t_start + modeled_compute_s`.
- `/transmit` body: `{grant, world_assertion, payload_b64, params:{payload_mb?}}` → `{attestation, delivered_bytes}`.
- Events pushed to `SIM_URL/events`: `provider_online, payment, grant_issued, grant_rejected, grant_fulfilled, refund, capacity_revoked, capacity_changed` (all include `node_id, operator_id, ts`).
- Pay rails: `tempo` (Tempo testnet, each operator has its own recipient wallet, no Stripe account needed), `stripe` (Stripe sandbox machine payments via `mppx/stripe/server`: SPT + Tempo), `mock`.
- Dev helper: `npx tsx scripts/mkassert.ts <window_id> <sim_t> [open] [bandwidth_mbps]` mints a World Assertion with `keys/world.json`.

## 3. Marketplace MCP (TypeScript, mcp-use v2, :3000/mcp) — "Broker"
Env: `SIM_URL`, `REGISTRY_SEED` (comma-separated operator base URLs), `MPPX_PRIVATE_KEY` (broker wallet, Tempo testnet), `PAY_RAIL`, `BROKER_KID`.
HTTP (non-MCP) routes: `POST /registry {manifest_url}` (fetch, verify sig, store), `GET /registry`, `POST /transfer/stream {mission_id, operator_id, grant, world_assertion, payload_b64, bytes_mb}` → opens an MPP session with the relay's `/transmit/stream` using the broker wallet, forwards `transfer_progress` (+`usd_accrued`) to the sim, records a `{method:"mpp-session"}` payment and returns `{ok, attestation, metered_usd, units, receipt_ref, settlement_refs}`.
MCP tools (zod in/out schemas, `structuredContent` always):
| Tool | Input | Output |
|---|---|---|
| `discover_providers` | `{capability?, min_window_start?}` | `{providers:[Manifest + live capacity + verified:true/false]}` |
| `get_contact_windows` | `{node_ids?}` | sim `/windows` |
| `request_quotes` | `{mission_id, legs:[{node_id, capability, window_id, units}]}` | `{quotes:[Quote]}` (fan-out, verify sigs) |
| `plan_mission` | mission fields + `now?` + `preserve?` | sim `/plan` result + one-paragraph `explanation` per plan |
| `reserve_path` | `{mission_id, plan_id, holder}` | holds all legs → pays each `/reserve` via `mppx/client` fetch wrapper (broker wallet) → `{grants:[…], receipts:[…], total_usd}`; on any hold failure → releases, `{ok:false, reason}` |
| `submit_mission` | `{mission_id, plan_id, resume?}` | sim `/missions` |
| `get_mission_status` | `{mission_id}` | sim mission + **MCP App view** `mission-status` (timeline, legs, payments, result thumbnail) |
| `reconcile_mission` | `{mission_id}` | OCGP §2.9: per-grant rows with checks `receipt_present, grant_sig_valid, price_within_quote, attestation_present, attestation_sig_valid, attestation_matches_grant, usage_within_limits, refund_voucher_valid` → `{ok, summary, rows, violations}`; violations mark the provider `trusted:false` in the registry and emit `reconcile_violation`. Also `GET /reconcile/{mission_id}`. Judge fixture: `/disrupt {type:"misbehave", node_id, mode:"over_attest"}` → operator `/admin/misbehave` (next attestation over-reports usage). |
| `inject_disruption` | `{type, …}` | sim `/disrupt` (judge tool) |
| `reset_world` | | sim `/reset` |
Also expose a **resource** `ocgp://protocol` returning docs/PROTOCOL.md so an unfamiliar agent can read the rules. Optional: gate `reserve_path` itself with MPP-over-MCP (`mppx` `Transport.mcpSdk()`) when `MPP_GATE_TOOLS=1`.

**As implemented (packages/marketplace):** extra HTTP routes `GET /health`; extra resource `ocgp://scenario` (data/scenario.json); prompt `run_mission`. `discover_providers` input is `{capability?, include_offline?}` (no `min_window_start`). `plan_mission` takes no `quotes` input — it always gathers quotes itself (sim `/plan` without quotes → one `/quote` per (operator, capability, window) → sim `/plan` with quotes) and returns `{…, now_sim_t, deadline_sim_t, budget_remaining_usd, quotes, quote_errors}`; `budget_remaining_usd` = mission budget minus payments already made. `reserve_path` returns `{ok, reason, plan_id?, grants, receipts, total_usd}`; receipts carry `method` (`tempo`/`spt`/`mock`) and `receipt_ref` (Tempo tx hash / Stripe PaymentIntent). It skips legs that already hold a grant (so a resume only pays new legs). `submit_mission` refuses plans with unpaid legs. `MPP_GATE_TOOLS` is NOT implemented. Legs fields may be `null` from the sim; all leg/plan/manifest schemas are passthrough + nullish.

## 4. Buyer agent (TypeScript, Anthropic SDK `claude-fable-5-1`, MCP client to marketplace)
Loop: read mission text → `discover_providers` → `get_contact_windows` → `request_quotes` → `plan_mission` → choose (LLM explains) → `reserve_path` → `submit_mission` → poll `get_mission_status` every 2 s → on `REPLAN_REQUIRED` rerun discover/quotes/plan with `preserve` → reserve → `submit_mission {resume:true}` → stop on DELIVERED/INFEASIBLE. Streams its reasoning to sim `POST /events {type:"narration"}` so the dashboard shows it. CLI: `npm run buyer -- --mission data/scenario.json [--auto]`.

## 5. Dashboard (React + Vite + react-globe.gl, :5173)
Reads `SIM_URL` (default `http://localhost:8000`), subscribes to `/ws`. Panels: 3D Earth (blue-marble + night lights + atmosphere), satellites with real orbit trails, ground stations, VIIRS hotspots (from `data/viirs_24h.csv` filtered to scene bbox), link arcs that light up while a window is open with a moving byte-progress indicator, mission HUD (sim clock, deadline countdown, budget vs spent), plan comparison table, provider cards (capacity, power, price, grants), live payment ticker (receipt refs link to Tempo testnet explorer / Stripe), audit feed, narration panel (acts), result overlay (fire polygons on the scene image), and `/judge` route (phone): buttons for every `scenario.disruptions` entry + clock controls.

### Fidelity (sim, added 2026-10-18)
Mission fields: `fidelity` ("full"), `degraded` `{label, payload_mb, fidelity:"low", note}`, `required_fidelity` ("full"|"low"|"any", default "any"). `/plan` honours them (defaults from the running mission's overrides, else the scenario). Every plan now carries `fidelity`, `tradeoff` (e.g. "fastest · full fidelity", "cheapest · low fidelity · +6 s", "cheapest full fidelity · full fidelity · +600 s (late)") and `payload_mb`. Raw routes get an extra **low-fidelity** candidate carrying `degraded.payload_mb` (label "Low-fidelity raw crop (40 MB) via …"); with `required_fidelity:"full"` those are infeasible ("mission requires full fidelity"). Intermediate nodes must offer relay capacity unless they are the compute node. For a low-fidelity plan the runner builds a REAL deliverable (Pillow 1/8 downsample of the scene, JPEG q70) as `result {kind:"raw_crop", fidelity:"low", summary, thumbnail_b64, geojson:[]}`, sets `committed` to the source node with the modeled `result_mb`, and the `/transmit` payload is that result (`bytes_mb` stays the modeled 40 MB). `mission_status`/`delivered` events and the mission object carry `fidelity`.
